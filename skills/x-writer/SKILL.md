# x-writer：我的推特文风

叙述者永远是我本人。这个 skill 管「怎么说」，「说什么」必须来自我给的素材或查得到的事实。

## 写之前先读

1. [references/voice.md](references/voice.md)：我的文风画像和原话样本。每次都读。
2. [references/genres.md](references/genres.md)：经验帖和教程长文两种文体，规则不同。每次都读，先定文体。
3. [references/taboos.md](references/taboos.md)：禁区和交付前自检，按文体适用。每次都读。
4. [references/x-format.md](references/x-format.md)：平台格式（字数计算、推文串、长推、X Article）。
5. `samples/` 里最近 2～3 组 `draft.md` / `final.md`：看我最近是怎么改稿的，比画像更新、更准。
6. 写教程长文时，再读 `references/exemplars/` 里的范例拆解。

## 流程

### 1. 吃透素材，定形式

- 先列出素材里能用的「硬货」：我亲手做过的事、实测数字、报错原文、踩坑经过、我当时说过的话。推文立不立得住全靠这些。
- 先按 genres.md 定文体：主要讲「我踩了什么、我怎么看」是经验帖，主要讲「从零怎么装、怎么配、怎么用」是教程长文。
- 经验帖再定形式：一个点写单条；3 个以上独立的点写推文串；要讲来龙去脉、要贴命令写长推（需要 X Premium）。拿不准就两种都给。
- 教程长文固定交付 X Article 正文加一条钩子推。
- 素材里没有亲身经历、只有二手信息时，直说「这条更像资讯整理」，问我要不要补自己的体验。最多问三个问题，一次问完。

### 2. 分清哪些不能编

- 不编第一人称的经历、情绪、对话、数字。素材里没有的感受（「我当时就愣住了」）不写。
- 只在社区帖子里看到的内容，写成「看到有人说」「帖子里说」，不写成我的经历。
- 官方规则、价格、条款这类会被人较真的事实，没核实过就去查原文；查不到就不写，或者标「待核实」。
- 隐私：不写邮箱、主机名、IP、内网域名、公司名、账号 ID、项目号、token。素材里有就脱敏。

### 3. 写

按 voice.md 的画像写。几条最要紧的：

- 开头直接上事：一句交代我干了什么、遇到了什么，不铺背景。
- 一个点一个具体细节：报错原文、数字、我做了什么，比形容词有用。
- 判断要敢下，用「我觉得」「我更喜欢」，不确定就说不确定。
- 口语，但不是语音转写：保留「其实」「对了」「怎么说呢」这种口头味，删掉「嗯」「就是就是」之类的冗余。
- 一篇只收一次尾，不写「总之」「一句话总结」。
- 教程长文按 genres.md 的骨架写：带数字的场景开头、目录、小标题直接写结论、固定模块（这一步注意、怎么确认生效了、一键指令、我踩过这个坑），结尾给选择表和「我的组合」。

### 4. 自检

按 taboos.md 末尾的清单过一遍。推文串和单条推文用脚本算字数：

```bash
uv run scripts/x_length.py <文件>            # 按 1/、2/ 分段逐条计数
uv run scripts/x_length.py --text "一条推文"  # 算单条
```

超过 280 的拆开或删减，不压缩成电报体。

### 5. 交付

- 把稿子存成 `samples/<YYYY-MM-DD>-<主题>/draft.md`，顶部写明素材来源和形式。
- 回复里只给：稿子路径、哪几处是你替我下的判断或需要我补的细节、哪些事实是查来的（附链接）。不附自评分和改动说明。
- 提醒我：发出去之前改一遍，改完把终稿发给你，你会存成 `final.md` 并学习。

## 学习我的改动

我说「这条我改好了」「学一下我的改动」，或者贴回一篇改过的稿子时，按 [references/learning-loop.md](references/learning-loop.md) 做：存终稿 → 对比 → 归纳 → 更新 voice.md。这一步是这个 skill 越用越像我的关键，不要跳过。
