# 文体：先定写哪一种

动笔前先判断这篇属于哪一类。两类的结构规则不同，taboos.md 里的禁区按文体适用。

| | 经验帖 / 踩坑帖 | 教程长文 |
|---|---|---|
| 读者为什么点开 | 想听你遇到了什么、你怎么看 | 想照着做，做完能用 |
| 形式 | 单条、推文串、长推 | X Article + 一条钩子推 |
| 结构 | 一口气顺下来，靠口语转场 | 编号大节、结论式小标题（不写目录） |
| 冒号 | 少用 | 小标题和段首的「结论：」可以用 |
| 成功的信号 | 转发、评论 | 收藏数高于点赞数 |

一篇里两种都有时，按主体定。素材主要是「我踩了什么坑」，写经验帖；主要是「从零怎么装、怎么配、怎么用」，写教程。

## 教程长文怎么写

范例拆解见 [exemplars/leaf-agy-t3.md](exemplars/leaf-agy-t3.md)。

### 钩子推

长文要配一条短推，只做三件事：
1. 表态，带情绪：用一句很冲的话说清结论。情绪是我的，素材里没有的情绪不编。
2. 给理由：一句「我实测下来……」。
3. 给承诺和动作：多长、能得到什么、「先收藏」。

### 开头三段

1. 一个具体场景，带数字，最好是痛点（「等了 10 分钟，界面还停在思考了 78 秒」）。
2. 反差：换一种做法之后发生了什么，带上我做过的、有数字的成果当背书。
3. 范围：这篇讲什么、不讲什么，一句话说完。不放别人文章的链接，也不点名推荐别人的教程。

需要时再加一段「开始之前，先分清两个东西」，把读者最容易混的概念拆开。

### 正文

- 不写目录。X Article 里的目录只是纯文本，点不了，也跳不到对应章节，白占开头的篇幅。章节靠编号小标题区分，比如「二、网络：TUN 必开，DNS 要理干净」。
- 小标题直接是结论：「会员：直接买 Pro。」「选模型：日常用 A，难活用 B。」读者只看小标题也能拿走结论。
- 每节按「是什么 → 怎么做 → 我的实测 → 坑」展开，命令能复制就给命令。
- 第一次出现的术语当场解释，最好配一个类比（「ACP 可以理解成一个标准插头」）。
- 照顾新手的话放在门槛最高的地方（「不会用终端也别怕，每条命令都是复制、粘贴、回车」）。

### 固定模块

这几种模块在全文里反复用，读者会形成预期。名字固定，不要每次换说法：

- **这一步注意：** 最容易翻车的一个点，一两句。
- **怎么确认生效了：** 一个能立刻验证的动作和预期结果。
- **一键指令：** 一段可以直接复制给 agent 的指令，代码块包起来。2026 年的读者很多是让 agent 照着做的。
- **我踩过这个坑：** 真实踩过的坑，配数字（跑了多久、花了多少）。

### 结尾

1. 一张「什么活用哪个」的选择表。
2. 一句「我的组合」，把自己的用法收成一句话。
3. 回扣开头的场景，换个角度再说一遍。
4. 一个具体的分享动作，指明转给谁（「转给还在 App 里干等的朋友」），再加一句评论区互动。

### 配图

需要截图的位置写 `[图：<截什么，证明什么>]`，比如 `[图：/usage 三个额度池]`。封面按 5:2 横图（1500×600）准备。
